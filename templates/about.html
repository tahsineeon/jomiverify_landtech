PROJECT NOTES

About JomiVerify

A feasibility-first prototype for the Digital Land Records, Verification & Digitization challenge.

Problem hypothesis

When land record details are kept only in paper files or scattered spreadsheets, searching, comparing and checking a copy can be slow, and duplicate entries can be difficult to spot. This prototype demonstrates a small structured workflow for intake, duplicate screening and integrity checks.

What it does

  • Stores record fields in a local SQLite database.
  • Searches by record ID, owner, location, khatian and dag.
  • Flags an exact repeated district/upazila/mouza/khatian/dag combination.
  • Uses a verification code and SHA-256 fingerprint as a basic integrity check.
  • Logs creation and verification events.

Important limits

This is a hackathon demonstration with synthetic data. It does not connect to Bangladesh government land systems, verify deeds, authenticate identity, determine ownership, or prevent a privileged operator from changing both data and hash. Production deployment would require authorized data access, role-based access, stronger audit controls, privacy review, and validation with land administration experts.
